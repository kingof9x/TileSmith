Cue 1 · Doors at 8 AM

How TileSmith works

A backstage tour of an LED wall app, for people who run servers, write the odd script and wonder what actually happens inside a program. No developer degree needed. Hard hat optional.

Scroll, swipe, or use ← → / Space to move between cues. Some slides have things you can click.

Cue 2 · The gig

What the app is for

An LED wall is a grid of tiles (cabinets) bolted together. A processor feeds them video over network cable. Before load-in, somebody has to work out the pixel map, the weight, the power and the cabling.

  • Lay out one or more walls on a canvas, the video raster a media server sends (say 1920 × 1080).
  • Paint test patterns on them so the crew can spot a bad tile from across the arena.
  • Do the engineering maths: pixels, kilos, watts, amps, processor ports, power circuits.
  • Send the result out live over the network (NDI®), to other apps on the same machine (Spout / Syphon), or to video, PNG, PSD and PDF.
  • And, because touring is long, a little technician walks out and builds the wall tile by tile.
Sysadmin translation

Think of it as capacity planning for a rack, with a live dashboard bolted on. Tiles are servers, the processor is the core switch, power circuits are PDUs, and the test pattern is the blinkenlights that tell you which box is dead.

Cue 3 · The big reveal

The whole app is one web page

Nearly everything TileSmith does lives in a single file: tilesmith-desktop/app/index.html. HTML for the layout, CSS for the looks and JavaScript for the brains, all in one place. No framework, no build step, no server.

~6,300lines in index.html (some of them very long)
~2 MBfile size, of which about 0.8 MB is pictures stored as text (base64)
0frameworks. Plain JavaScript and the browser's own 2D drawing canvas
Sysadmin translation

It is the one-giant-bash-script approach, done on purpose. Like a self-extracting installer with its payload glued to the end, the test pattern images ride inside the file as base64 text. You can copy one file to a USB stick and the app goes with it. Open it in Chrome or Firefox and it runs in web mode.

Cue 4 · The road case

Electron: a browser that thinks it's an app

A web page can't talk to network video drivers or write files wherever it likes. So the desktop app ships the page inside Electron: a copy of the Chromium browser plus Node.js, the JavaScript runtime people use for servers.

The part outside the page, main.js, is only 66 lines. It opens the window, loads index.html, keeps the app awake while it is sending video, opens full-screen output windows on other displays, takes bug-report screenshots, and hands over to the installer when you update.

Main processmain.js · window manager, displays, power blocker, updater
IPC messages ("ts-displays", "ts-capture", "output-active")
Renderer: index.htmlthe whole app: UI, maths, drawing, patterns, animation
Node.js calls straight from the page
Your computerfiles, ffmpeg, NDI® runtime, SpoutDX.dll, Syphon
Sysadmin translation

Chromium in kiosk mode, with a tiny supervisor daemon next to it. IPC is like a local socket between the two: one side asks "which monitors are plugged in?", the other answers.

Cue 5 · The show file

Everything you set lives in one object called S

Canvas size, border colour, which processor, the crew's names: every setting is a key in one JavaScript object. Each wall has its own object too. The UI always edits S; when you pick another wall, that wall's settings are copied in and out.

Change anything and, 400 ms after you stop fiddling, the app writes it all to disk as JSON. On load it checks every value's type and clamps it to its limits, so a hand-edited file can't set the canvas to minus four pixels.

// state.json (shortened)
{
  "sv": 23,            // save format version
  "S": {
    "cw": 1920, "ch": 1080, // canvas size
    "bc": "#22d3ee",      // tile border colour
    "ids": true,          // show tile IDs
    "speed": 1            // build animation speed
  },
  "walls": [ { /* one per LED wall */ } ],
  "crew": [ /* Marcus, Elena, ... */ ]
}
Sysadmin translation

A config file that rewrites itself, with input validation on read. It lives in %APPDATA%\TileSmith on Windows and ~/Library/Application Support/TileSmith on a Mac. In a browser it goes in localStorage instead. "Reset saved settings" is rm state.json with a nicer button.

Cue 6 · The render loop

Redraw the wall 60 times a second

The picture you see is not stored anywhere. Each frame the app wipes the canvas black and paints it again, layer by layer, like a scenic painter who works back to front.

When nothing moves it slows down to four redraws a second, a safety net that costs almost nothing. Tick the layers on the right to see each one go on.

Sysadmin translation

A cron job that fires every 16.7 ms and regenerates a report from scratch. Stateless and dumb on purpose: if something goes wrong in one frame, the next one fixes it.

Cue 7 · Test patterns

A test pattern is just arithmetic

There are about 25 patterns. Most aren't pictures at all; they're a few lines of maths run for every tile. Take tileshade-cycle: every tile cycles red, green, blue, and no tile ever matches its neighbour.

colour = [red, green, blue][(col + 2 × row + k) mod 3]
// k goes up by one every 2.5 seconds

Step one column right and the number goes up by 1. Step one row down and it goes up by 2. Neither is a multiple of 3, so neighbours always differ. That's the whole trick.

Live: the same formula, running in your browser right now.

Cue 8 · Data

Processor ports are uplinks

Each processor port drives a daisy chain of tiles over a network cable. A port can only carry so many pixels (a NovaStar 1G port: 650,000 at 60 Hz, 8-bit). Fill it and you need another port.

tile pixels    = tile width × tile height
tiles per port = floor( port pixels ÷ tile pixels )

TileSmith knows the figures for about 30 processors (Brompton, NovaStar, Megapixel, ROE), adjusts them for frame rate and bit depth, then snakes the cable through the wall and labels the ends P1 (port) and R1 (return).

Sysadmin translation

Bandwidth planning. A 1 Gb uplink can only carry so much, and a return cable at the end of the chain is your redundant path, like closing a ring.

Cue 9 · Power

Don't trip the breaker

Each circuit can only feed so many watts. TileSmith works out how many tiles fit on one, chains them up, and spreads circuits across the three phases of a distro so no leg is overloaded.

usable watts = volts × amps × 0.8 × power factor
tiles per circuit = floor( usable watts ÷ tile max watts )

The 0.8 is the "load circuits to 80%" rule electricians use for continuous loads. A Socapex cable carries 6 circuits, so circuit 7 starts cable 2.

Sysadmin translation

Exactly the sum you do before racking another server on a PDU, with the same 80% headroom habit.

Cue 10 · Getting the picture out

Three ways out of the box

Every frame, the app reads the finished canvas back as raw pixels (red, green, blue, alpha: 4 bytes each, so a 1920 × 1080 frame is about 8 MB) and hands the same buffer to whoever wants it.

NDI®video over your network. Media servers on the LAN see "TileSmith" as a source.
same frame
Spout / Syphonshares the picture with other apps on the same computer through the graphics card. No network, no compression.
same frame
ffmpegraw frames are piped into ffmpeg, which writes MP4 or HAP video.
Sysadmin translation

ffmpeg is driven exactly like you'd drive it from a shell: ... | ffmpeg -f rawvideo -pix_fmt rgba -i - out.mp4. The app is just the thing on the left of the pipe.

Sysadmin translation

NDI® and Spout are C libraries (a .dll / .so). A small add-on called koffi lets JavaScript call their functions directly, the way Python's ctypes does. No compiler involved.

The status line shows the per-frame budget, for example: render 0.4 ms, read 10.1 ms, send 0.0 ms. Reading pixels back off the graphics card is the slow part.

Cue 11 · Enter the crew

The technician is a state machine

For every tile, the tech goes through the same five phases, then starts on the next tile. The tile only "lights" (shows the pattern) once it locks in.

walk in0.8 s
move1.1 s
place0.8 s
lock0.6 s
walk out1.5 s

Each wall runs at a slightly different speed and starts a little later than the last, so a show with four walls doesn't look like a synchronised swimming team. The crew rotates so one person is never on two walls at once.

The Hand-drawn style uses real motion-captured workers rendered in 3D (three.js), then inked like a cartoon. Those files are about 5 MB, so they only load when you pick that style.

Sysadmin translation

Same idea as a service going starting → running → stopping → stopped. Each phase has a timer; when it runs out, move to the next state. Loading the 3D crew only when asked is lazy loading, like a kernel module that is only inserted when the hardware shows up.

Cue 12 · Intermission

Yes, it hits the corner

There is a DVD screensaver. Of course there is. And because this is a serious engineering tool, it has a dial for how often the logo lands exactly in the corner.

After each bounce the app rolls the dice. On a hit it "unfolds" the walls like mirrors and picks a straight line that reaches a corner. On a miss it nudges the angle just enough to dodge one.

The perfect loop option picks two whole numbers with no common factor so the logo ends up exactly where it started, in the same colour, after a set time. Export that as a video and it loops forever without a seam.

Cue 14 · Load-out

How a release ships itself

Nobody builds TileSmith on their laptop. Pressing one button on GitHub starts a chain of robots (GitHub Actions) on rented machines.

  • Every proposed change gets a test build before it is merged, so a broken build never reaches the main branch.
  • The app's Check for updates reads the latest GitHub release and offers the file that matches your system.
  • The builds are unsigned (certificates cost money every year), which is why every file is scanned on VirusTotal and the results are published next to the code.
Build and releaseWindows .exe, Mac .dmg/.pkg, Linux AppImage, .deb, .rpm, .pacman, Snap, Flatpak, Android .apk
then, by itself
Build documentationPython drives a headless browser, takes screenshots of the real app, circles the buttons and writes the PDF manuals
then, by itself
VirusTotal scanuploads every file and writes the results to VIRUSTOTAL.md
Sysadmin translation

A CI pipeline, or three Ansible playbooks chained with handlers. Each stage only starts when the last one succeeds.

Cue 15 · Your turn

Poke at it yourself

It's open source (GPL-3.0), so you can read every line. A good first evening:

# get the code
git clone https://github.com/kingof9x/TileSmith
cd TileSmith/tilesmith-desktop

# run the desktop app (needs Node.js)
npm install
npm start

# or skip all that: open app/index.html in a browser
# (web mode: everything except NDI®, Spout, Syphon and video export)
Where to start reading

TileSmith-App-Spec.md describes every feature, number and formula in plain English. It's written so that someone could rebuild the app from it, which also makes it the best map of the code.

Things to try

Search index.html for tileshade and change a colour. Find the crew names and add yours. Break something, then put it back. That's how everyone learned.
